## What's New in v0.12.3

A single fix: `cc-clip update` no longer stops when GitHub's API rate limit is used up.

### `cc-clip update` works behind a shared, rate-limited IP

Looking up the latest release used only the GitHub API, which allows 60 unauthenticated requests per hour per public IP. Behind a university or company NAT that budget is shared with everyone on the network, so `update` could fail without you having run it at all:

```text
failed to query latest release: GitHub API returned 403: {"message":"API rate limit exceeded for ..."}
```

`update` now falls back to the `github.com/ShunmeiCho/cc-clip/releases/latest` redirect, which is not rate-limited and never points at a draft or prerelease. If both lookups fail, the error says when the limit resets and how to update anyway (`--to vX.Y.Z`, or `GH_TOKEN=$(gh auth token)`). `scripts/install.sh` gets the same fallback, and a failed lookup there explains how to pin a version with `CC_CLIP_VERSION`. (#170, #171)

## Other Improvements

- A daemon test that failed intermittently under `-race` now publishes the recorded notification before its delivery count. Test-only; no behaviour change. (#169, @paigeman)

## Upgrade

This update itself runs your current version's lookup, so on a rate-limited network it can still hit the 403. Name the version to skip the lookup:

```bash
# macOS / Linux, existing install
cc-clip update --to v0.12.3

# macOS / Linux, fresh install (install.sh already has the fallback)
curl -fsSL https://raw.githubusercontent.com/ShunmeiCho/cc-clip/main/scripts/install.sh | bash
```

```powershell
# Windows, install or upgrade. If the installer stops with a GitHub API
# rate-limit error, pin the version first:
$env:CC_CLIP_VERSION = "v0.12.3"
irm https://raw.githubusercontent.com/ShunmeiCho/cc-clip/main/scripts/install.ps1 | iex
```

Nothing changed on the remote side in this release, so `cc-clip connect <host> --force` is optional; it only updates the version the host reports.
