## What's New in v0.12.0

### Paste works on Wayland-only remotes, and with Kimi Code and MastraCode

Current Claude Code lists clipboard types with `wl-paste -l`, which the shim did not recognize, so on a remote with no working `xclip` paste fell through to the real `wl-paste` and failed. The shim now intercepts the exact `-l` token (`--list` and `-lh` still pass through unchanged).

The same release adds the read shapes two more agents use: Kimi Code's `wl-paste -t image` and MastraCode's `xclip -target image/...` / `-target TARGETS`. Both are verified against their source and by shim tests, not yet end to end with the real CLIs.

### `cc-clip uninstall` puts your own program back

If you installed with `--adopt-foreign-shim`, your program was moved to `<path>.cc-clip-real`. Running `cc-clip uninstall` on that host now moves it back to `<path>` and removes the shim, in one atomic swap on Linux and macOS. For a `wl-paste` install, the `wl-copy` companion is restored the same way.

Uninstall never deletes or overwrites a program it did not write. If another process changed `<path>` or `<path>.cc-clip-real` in the meantime, or the filesystem cannot do the atomic swap, uninstall stops and says what it left where; when a restore was due, it also prints the `mv` command to finish by hand. If a Wayland uninstall stops halfway, running it again finishes the rest.

### `connect` tells you why the remote install was refused

When a file cc-clip did not write sat at the shim path, `cc-clip connect` only printed `remote install failed: : exit status 1`. It now shows the remote's reason and the `--adopt-foreign-shim` flag that lets you proceed:

```bash
cc-clip connect <host> --adopt-foreign-shim
```

### `doctor` shows whether notifications actually arrived

`cc-clip doctor --host <host>` used to check only that a notification hook is wired, not that it fires. The daemon now records when it last accepted a notification from each host and CLI, and doctor prints one of three states per CLI:

```text
  delivery-receipt:claude: [pass] last notification accepted 2h13m ago
  delivery-receipt:codex: [pass] stale: last notification accepted 9d4h ago (older than 7d0h)
  delivery-receipt: [pass] never received from: cursor, opencode, agy (fine for any you do not use on this host)
```

None of these fails the check. This is the way to confirm the notification paths that have not been tested on real hardware (opencode, Antigravity, Cursor, Windows): if doctor shows a recent receipt, the path works on your machine.

## Other Improvements

- Stopping the Codex virtual display now identifies the Xvfb process through `/proc` instead of `ps -p`, which BusyBox does not support, and never kills a process it could not identify.
- Releases can no longer publish without user-facing notes; v0.11.1 shipped with only a commit list because that step was manual.
- More daemon tests: JPEG clipboard reads and token handling at startup.

## Behaviour Changes to Know

- **`cc-clip uninstall` restores an adopted program** instead of leaving it at `<path>.cc-clip-real`.
- **`cc-clip uninstall` can now refuse** with nothing changed, where it used to delete: when a concurrent change or a missing filesystem capability means it cannot tell that what it would remove is still its own shim. The message names every entry and the manual command.
- **`cc-clip doctor --host` prints extra lines** for notification receipts. They are informational and never change the exit status.

## Upgrade

**Local machine first, then each remote host.**

```bash
# macOS / Linux, existing install
cc-clip update

# macOS / Linux, fresh install
curl -fsSL https://raw.githubusercontent.com/ShunmeiCho/cc-clip/main/scripts/install.sh | bash
```

```powershell
# Windows, install or upgrade
irm https://raw.githubusercontent.com/ShunmeiCho/cc-clip/main/scripts/install.ps1 | iex
```

Then, for every remote host (this deploys the new shim and the new `cc-clip` that uninstall runs):

```bash
cc-clip connect <host> --force
```

## Not in This Release

- **Kimi Code and MastraCode paste are not verified end to end** with the real CLIs. Reports welcome.
- **Windows, opencode, Antigravity and Cursor notification paths** are still not verified on real hardware by us; `doctor --host` receipts now let you check your own.
- **An uninstall killed mid-way is not recovered automatically.** Nothing is deleted: a program can be left under a hidden `.<name>.cc-clip-uninstall-<hex>` name in the same directory, from where you can move it back.
- **Persistent per-host SSH tunnels** (#108) are being worked on by a contributor; **notification icon/sound settings** (#92) remain open.
