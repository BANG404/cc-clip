## What's New in v0.12.1

A small fix release: two flags that were documented but did nothing now behave as the help says.

### `cc-clip notify --port` works

`cc-clip notify --port <n> ...` used to stop with `flag provided but not defined: -port`, so a notification could reach a daemon on a non-default port only through `CC_CLIP_PORT`. The flag is now accepted, wins over `CC_CLIP_PORT`, and a non-numeric value is rejected:

```bash
cc-clip notify --port 18340 --title "Build done" --body "all tests passed"
```

### `cc-clip setup` refuses flags it would have ignored

`setup` accepted `--force`, `--token-only`, `--adopt-foreign-shim`, `--no-hooks`, `--hooks` and `--no-notify` and then silently did nothing with them, so for example `setup myserver --adopt-foreign-shim` still stopped at a foreign `xclip`. It now stops before doing any work, names each flag, and prints the command that does honour it:

```text
error: --adopt-foreign-shim is a connect flag; run "cc-clip setup myserver" first, then "cc-clip connect myserver --adopt-foreign-shim"
```

## Other Improvements

- The Chinese and Japanese READMEs now carry the v0.12.0 feature guide and full command list.
- CI fails when a translated README falls behind the English one, so the translations cannot silently lag again (they had since v0.10.0).

## Behaviour Changes to Know

- **`cc-clip setup` exits with status 2** when given any of the flags above. A script that passed them to `setup` should run `setup` first and then `connect` with the flag.

## Upgrade

**Local machine first, then each remote host.**

```bash
# macOS / Linux, existing install
cc-clip update

# macOS / Linux, fresh install
curl -fsSL https://raw.githubusercontent.com/ShunmeiCho/cc-clip/main/scripts/install.sh | bash
```

```powershell
# Windows, install or upgrade
irm https://raw.githubusercontent.com/ShunmeiCho/cc-clip/main/scripts/install.ps1 | iex
```

Then, for every remote host (`notify` runs there, so `--port` needs the new remote binary):

```bash
cc-clip connect <host> --force
```

## Not in This Release

- **Kimi Code and MastraCode paste are not verified end to end** with the real CLIs. Reports welcome.
- **Windows, opencode, Antigravity and Cursor notification paths** are still not verified on real hardware by us; `cc-clip doctor --host` shows when each last delivered a notification on your machine.
- **Persistent per-host SSH tunnels** (#108) are being worked on by a contributor; **notification icon/sound settings** (#92) remain open.
